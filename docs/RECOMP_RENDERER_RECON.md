# Independent renderer reconnaissance — 2026-10-16

## Finding and evidence boundary

**No proven matching Monster Games / NASCAR Heat / Dirt to Daytona / Test Drive: Eve of Destruction PS2 static recompilation or decompilation targeting Metal/Vulkan was found.** This is a bounded public-source search, not proof that none exists. Queries covered those game/developer names plus PS2 recompilation, decompilation, Metal, Vulkan and racing. No private chats, game execution, builds or GPU workloads were used. Local `AGENTS.md` and `RENDERER_REFERENCES.md` supplied requirements only; their conclusions were not treated as independent evidence.

Road Trip is a relevant racing PS2 static recompilation with a published Mac package and test harness. That establishes an inspectable candidate, **not a correctness oracle or proof of matching EOD transfers**. Its forks, PS2Recomp integrations and bundled paraLLEl-GS are one dependency lineage, not several independently successful ports.

## Concrete code paths and reusable invariants

### PCSX2: preserve GPU data outside the actual CPU write

[`GSTextureCache.cpp`](https://github.com/PCSX2/pcsx2/blob/685637d30b5eaa8e5d7a587673a17577a92dcb88/pcsx2/GS/Renderers/HW/GSTextureCache.cpp) separates `InvalidateVideoMem` (host writes invalidate/update GPU views), `InvalidateLocalMem` (GPU output needed in local memory), `Read(Target*, rect)` and `Target::Update`. `Target::Update` at line 8040 stages a total dirty region but iterates actual dirty rectangles, with channel masks. Its comment at ~8119 explicitly warns that block-aligned writes corrupt GPU-only pixels: local memory can be stale after hardware local copies. Read granularity and write granularity are different.

**EOD application:** track CPU dirtiness separately from GPU validity, preserve untouched pixels/channels for partial writes, and never expand a CPU upload over authoritative GPU pixels merely because allocation or swizzle blocks are larger. Prefer focused fixtures for overlapping CPU upload, GPU draw, local copy, palette/format aliasing and later readback before changing ownership policy. PCSX2 is a model to understand, not a small drop-in cache: it has many game-specific paths, hacks and validity assumptions.

[`GSTextureMTL.mm::GSDownloadTextureMTL::Flush`](https://github.com/PCSX2/pcsx2/blob/685637d30b5eaa8e5d7a587673a17577a92dcb88/pcsx2/GS/Renderers/Metal/GSTextureMTL.mm#L234) kicks a still-encoding copy, skips waiting if it already completed, otherwise spins or calls `waitUntilCompleted`. This supports **enqueue early, consume only after completion**, not “mapping shared memory eliminates synchronization.” [`GSDeviceMTL.mm`](https://github.com/PCSX2/pcsx2/blob/685637d30b5eaa8e5d7a587673a17577a92dcb88/pcsx2/GS/Renderers/Metal/GSDeviceMTL.mm) also has encoder fences and explicit readback flushes.

[`tfx.metal`](https://github.com/PCSX2/pcsx2/blob/685637d30b5eaa8e5d7a587673a17577a92dcb88/pcsx2/GS/Renderers/Metal/tfx.metal) includes alpha-test variants, destination-alpha modes, destination-dependent shader blend arithmetic and bitwise framebuffer masking (`ps_fbmask`, ~1303). These are coupled with [`GSRendererHW.cpp`](https://github.com/PCSX2/pcsx2/blob/685637d30b5eaa8e5d7a587673a17577a92dcb88/pcsx2/GS/Renderers/HW/GSRendererHW.cpp) draw/feedback decisions. Copying only blend math without ordering, destination availability and depth/alpha writes is insufficient. `BeginPresent` / `EndPresent` distinguish presentation from command encoding; this is not evidence of a measured 60-on-120 cadence result for EOD.

### paraLLEl-GS: explicit ownership transitions, not unconditional whole-VRAM copies

[`GSInterface::flush`](https://github.com/Arntzen-Software/parallel-gs/blob/cc6184af7e0c03da603045ca371ffa5dae9b0655/gs/gs_interface.cpp#L353) collects host-write **blocks** and GPU-to-host **pages**, dispatching `flush_host_vram_copy`, `flush_readback`, transfer overlap barriers and render/cache flushes according to tracker flags. `flush_pending_transfer` preserves partially received transfers; palette/texture consumers flush pending data before accessing it. `map_vram_read` / `map_vram_write` at ~4194–4265 query the tracker, submit when necessary and wait on the relevant timeline before returning CPU pointers; `end_vram_write` commits host ownership.

**EOD application:** adopt the explicit transition vocabulary even if retaining decoded primitives. Accurate backend integration should mirror original packets and register state; it cannot be assumed compatible with a decoded-triangle API. Batch or defer reads only when the caller does not need their results yet. [`gs_renderer.cpp`](https://github.com/Arntzen-Software/parallel-gs/blob/cc6184af7e0c03da603045ca371ffa5dae9b0655/gs/gs_renderer.cpp) and [`sandbox/gs_test.cpp`](https://github.com/Arntzen-Software/parallel-gs/blob/cc6184af7e0c03da603045ca371ffa5dae9b0655/sandbox/gs_test.cpp) provide implementation and generated dump exercise paths; neither is a measured EOD workload. Read [upstream limitations/features](https://github.com/Arntzen-Software/parallel-gs/blob/cc6184af7e0c03da603045ca371ffa5dae9b0655/README.md) before treating the oracle as hardware truth. Road Trip's Apple-specific fork must be assessed separately from this upstream pin.

### Play!: a second implementation exposes the cost and risk of shortcuts

[`CTransferHost::DoTransfer`](https://github.com/jpd002/Play-/blob/d44bfa1814b729d4a3ed3c6c3a945432d5ee5bbe/Source/gs/GSH_Vulkan/GSH_VulkanTransferHost.cpp#L56) appends CPU data to per-frame staging storage, barriers prior shader accesses, then dispatches format-aware compute writes to GS memory. The generated shader distinguishes 32-/24-/16-bit writes; preserve-format semantics belong in the write path.

[`CGSH_Vulkan::ProcessLocalToHostTransfer`](https://github.com/jpd002/Play-/blob/d44bfa1814b729d4a3ed3c6c3a945432d5ee5bbe/Source/gs/GSH_Vulkan/GSH_Vulkan.cpp#L1469) flushes the render pass, computes source range, records a memory copy, and for non-recurring transfers flushes and waits for queue idle before mapping. Recurring transfers take a different history-dependent path; reads can also be disabled by preference. **Do not copy the skip-wait/read-disable policy into EOD without proving freshness and semantics.** This is useful contrary evidence to “another Vulkan renderer makes every readback cheap.”

### OpenGOAL: LOD and visibility need game semantics

[`drawable.gc`](https://github.com/open-goal/jak-project/blob/32c3cf73970f885c0a588623208232db72a74a58/goal_src/jak1/engine/draw/drawable.gc#L572) preserves original LOD distances behind `ps2-lod-dist?`, bounds actor overrides by `max-lod`, and keeps visibility/guard-band tests separate from LOD selection. `sphere-in-view-frustum?`, `sphere-cull`, `guard-band-cull` and distance checks are distinct consumers. [`VisDataHandler.cpp`](https://github.com/open-goal/jak-project/blob/32c3cf73970f885c0a588623208232db72a74a58/game/graphics/opengl_renderer/VisDataHandler.cpp) and [`OpenGLRenderer.cpp`](https://github.com/open-goal/jak-project/blob/32c3cf73970f885c0a588623208232db72a74a58/game/graphics/opengl_renderer/OpenGLRenderer.cpp) show the game-aware renderer boundary.

**EOD application:** a wider projection alone does not update CPU sphere/guard-band culling, streaming/PVS or LOD cutoffs. Recover and adjust the relevant EOD consumers, retain an original baseline and test edge objects across aspect ratios. Jak address/layout/constants do not transfer to Monster Games. No claim that raising LOD alone extends streaming or draw distance is supported by these sources.

## Apple portability and next decision

The [official MoltenVK runtime guide](https://github.com/KhronosGroup/MoltenVK/blob/main/Docs/MoltenVK_Runtime_UserGuide.md) describes Vulkan-on-Metal capabilities, portability restrictions and pipeline-cache/MSL behavior. Capability queries and actual workload tests are required; changing translation-layer settings does not remove CPU/GPU data dependencies. PCSX2's native Metal code is useful for Apple synchronization patterns, while its successful Mac distribution does not prove parity/performance for a different Vulkan implementation.

Recommended next narrow step: compare EOD's partial/masked uploads and deferred readback boundaries against PCSX2 and paraLLEl-GS with generated fixtures, then measure the exact representative workload in isolation. Keep game-specific widescreen/culling/LOD recovery separate from GS fidelity. No wholesale renderer replacement is justified by the evidence collected here. No source was copied into production; no commits or pushes were made. Public reference downloads are scratch material under ignored `work/recon-independent/`.
